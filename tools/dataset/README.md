# tools/dataset

Pipeline de build do dataset do Pontindex (Node 24 + tsx). Le os dados do All the Mons e escreve JSON + midia em uma pasta de staging; so a etapa final (B2.5) publica em `public/`.

## Uso

```bash
npm run dataset                                  # pipeline completo (publica em public/data/<datasetVersion>/)
npm run dataset -- --only speciesCore --out tools/dataset/out/_base --skip-media --report
```

| Flag | Efeito |
|---|---|
| `--instance <dir>` | fonte de dados (precedencia: flag > env `ATM_INSTANCE_DIR` > `data-source/atm-1.3.0`) |
| `--skip-media` | so JSON (media e sprites retornam cedo) |
| `--offline` | PokeAPI so pelo cache em disco |
| `--report` | imprime a tabela de contagens/tamanhos (sempre grava `<out>/report.json`) |
| `--keep-old` | nao remove versoes antigas de `public/data/` ao publicar |
| `--only <etapa>` | roda `speciesCore` + so a etapa pedida; NUNCA publica |
| `--out <dir>` | staging (padrao `tools/dataset/out/_staging`); precisa ficar dentro de `tools/dataset/out/` e e apagado a cada execucao |

Etapas, na ordem (`src/index.ts`): `speciesCore` (`species/merge.ts`) -> `speciesDerive` (`species/stage-derive.ts`) -> `pokeapi` (`pokeapi/stage.ts`) -> `media` (`media/stage.ts`) -> `balls` (`balls/stage.ts`) -> `trainers` (`trainers/stage.ts`) -> `items` (`items/stage.ts`) -> `write` (`species/index-writer.ts`).

## Fonte

O modo e decidido SO por `fs.statSync(<fonte>/mods/<jar>)` dos 7 jars obrigatorios (`Cobblemon-neoforge-`, `allthemons-`, `complete-cobblemon-collection-`, `legendarymonuments-`, `mega_showdown-`, `zamega-`, `rctmod-neoforge-`): todos diretorios = snapshot (`DirSourceReader`), todos arquivos = instancia real zipada (`ZipSourceReader`), mistura = `E_SOURCE_MODE_UNKNOWN`. Todo acesso a fonte passa por `SourceReader` (`src/source-reader.ts`).

## Saida

- Staging: JSON em `<out>/data/`, midia em `<out>/assets/{cries,sfx,items,sprites}/`, `report.json` e `merge-report.json` na raiz de `<out>`.
- Cache busting (U3): `items.json` grava `texture` como `assets/items/<ns>/<caminho>.png?v=<8 hex do sha256 dos bytes publicados>`; o arquivo em disco nao muda de nome, a query muda quando os bytes mudam (`src/media/asset-version.ts`).
- Drop de treinador (U5a): `items.json` ganha a rota `{ kind: "trainerDrop", trainers: [{ id, name, series, chance, levelRange, firstDefeatOnly }] }` a partir de `data/rctmod/loot_table/trainers/single/<trainerId>.json` (jar rctmod + kubejs; entradas diretas e um nivel de `rctmod:generic/**`; o loot de `trainers/groups/**` fica de fora). Codigo: `src/items/trainer-drops.ts`.
- Receitas (U7a): a rota `craftable` (`recipeTypes`) vem das receitas de TODOS os namespaces: `data/<ns>/recipe/**` (a pasta plural `recipes/` e do formato 1.20 e nao carrega no 1.21.1) de todo jar em `mods/` (snapshot: pastas; o snapshot guarda so as receitas que produzem itens do catalogo), do jar vanilla 1.21.1 (snapshot `vanilla/1.21.1.jar/`, instancia `../../Install/versions/1.21.1/1.21.1.jar`) e de `kubejs/data`; mesmo id = o de maior prioridade vale (vanilla < jars < kubejs). Saida lida das chaves de resultado (`result`, `results`, `output(s)`, `main_output`...), sem `sequence`/`transitional_item`. `neoforge:conditions`: `mod_loaded` contra `mod-ids.json` (snapshot) ou os `neoforge.mods.toml` dos jars (instancia); `productivebees:bee_exists` pelas definicoes `data/*/productivebees/**`; condicao de config de mod = receita fora (report `recipes.droppedForCatalog`). Remocoes do kubejs (`<evento>.remove(...)` literal em `kubejs/server_scripts/**`: id, regex de id, output/tag, type, mod) aplicadas; dinamicas e por `input` so listadas (`recipes.kubejsRemovalsUnparsed`). Receitas acrescentadas por script com saida literal (`shaped`, `shapeless`, `smelting`..., `custom({...})`) entram. Codigo: `src/items/recipes.ts`.
- Loot (U7b): `structureLoot`/`fishing` vem das loot tables de TODOS os namespaces: `data/<ns>/loot_table/**` do jar vanilla, de todo jar de `mods/` e de `kubejs/data` (mesmo id = vanilla < jars < kubejs), tabela com `neoforge:conditions` que nao passam fica de fora. Itens de uma tabela: `minecraft:item`, `minecraft:tag` (tags de item das mesmas fontes, aninhadas resolvidas), `minecraft:loot_table` (referencia em qualquer namespace, recursiva, ou inline) e filhos de `alternatives`/`group`/`sequence`. Categoria pelo caminho (`classifyLootTable`): bau/arqueologia/estrutura = `structureLoot` (id `<ns>:<caminho>`; cobblemon sem namespace e com a regra antiga, tudo que nao e pesca); `fishing` (pasta `fishing`, nunca `chests/fishing`); `sets/`, `selectors/`, `rctmod:generic/` so por referencia. U7c: `blocks/**` (inclusive cobblemon) = `blockDrop` `{ blocks: [{ id: <ns>:<bloco>, name }] }` (bloco que so derruba ele mesmo nao conta: `loot.blockSelfDrops`); `entities/**`, `bosses/**` e `inject(ion)/entities/<mob>` = `mobDrop` `{ mobs: [{ id, name }] }` (id `<ns>:<mob>`, variante como `sheep/blue` vira `sheep`; inject vira `minecraft:<mob>` so se a tabela vanilla existe; tabela de bloco/mob referenciada por outra so conta pela que a usa); `name` = lang do pack `block.<ns>.<caminho>` / `entity.<ns>.<mob>` ou null. Global loot modifiers (`data/neoforge/loot_modifiers/global_loot_modifiers.json` dos jars e do kubejs) com `addition.id` e SO condicoes `neoforge:loot_table_id` somam o item a tabela alvo (ex. `mega_showdown:red_orb` em `cataclysm:entities/ignis`). Gameplay, grupos de treinador rctmod (`trainers/groups/**`) e o resto NAO viram rota: ficam no report, secao `loot.pendingContract`. Codigo: `src/items/loot.ts`.
- Outras fontes (U7c, `src/items/extra-sources.ts`), cada uma so com prova num arquivo do pack: `questReward` `{ quests: [{ chapter, title }] }` (recompensa `item` e `random`/`loot`/`choice` via `reward_tables/*.snbt` de `config/ftbquests/quests/chapters/*.snbt`; titulos de `lang/{pt_br,en_us}.snbt`, sem codigos de cor, null sem chave); `shop` `{ shop: "battleTowerBp", price }` (`config/cobblemon_battle_tower/bp_shop_items.json`, `items[]` + `_default_items` quando `load_default_items`, sem entradas `command`); `structurePlaced` `{ structures: [{ id, name: null }] }` (`data/<ns>/structure(s)/**.nbt` de todo jar e de `kubejs/data`: `Items[]`, `item`/`Item`, `rewards[].item` no NBT de blocos e entidades; loja de NPC e equipamento de mob ficam de fora; leitor NBT proprio em `src/lib/nbt.ts`); `ritual` `{ rituals }` (`summoningrituals.altar(...)` em `kubejs/server_scripts/**`, `itemOutputs`/`displayOutputs`, id do `.id(...)`); `trade` `{ traders: ["wanderingTrader"] }` (`data/*/wanderer_trades/**`, `output.id`); `worldgen` `{ features }` (biome modifier `neoforge:add_features` -> placed -> configured feature que coloca o bloco de mesmo id do item, so para bloco que derruba ele mesmo); `special` `{ note, evidence }` (tera shards pela `config/mega_showdown/config.json` `teraShardDropRate`/`stellarShardDropRate`; `give_item` de `data/cobblemon/pokemon_interactions/*.json`). Leitor SNBT em `src/lib/snbt.ts`.
- Catalogo e `unobtainable` (U7d): chave de lang com sufixo (`item.<ns>.<path>.tooltip`, `.desc`...) nao cria id. Id so referenciado (treinador, evolucao, forma, fossil), sem textura e sem nenhuma rota no pack nao e item registrado e fica fora do `items.json` (aviso `W_ITEM_REFERENCE_UNKNOWN`; hoje `karrablast`, `shelmet`, `mega_showdown:darkinium-z`, `mega_showdown:mimikium-z`, `mega_showdown:baxcalibrite`); os treinadores continuam citando o id como esta no arquivo. Item sem nenhuma rota vira `{ kind: "unobtainable", reason }` (unica rota): `notRegistered` se esta em `curated/item-not-registered.json` (id -> prova), senao `creativeOnly`. `none` nao e mais emitido. Report: secao `items` (`unobtainable`, `phantomIds`, `obtainKinds`).
- Nomes e texturas do jogo (U8, `src/items/ref-names.ts`, `src/media/vanilla-textures.ts`): tabela de nomes SEPARADA do `ctx.lang` (que define o catalogo) com o lang en_us/pt_br de todo jar de `mods/` (ordem do nome do arquivo, o primeiro vence) e do Minecraft 1.21.1 (en_us do jar do cliente; pt_br do asset store do launcher pelo indice de `versions/1.21.1/1.21.1.json`; snapshot `vanilla/assets/minecraft/lang/pt_br.json`). Chave resolvida por `ctx.lang` (6 namespaces do app + kubejs por cima) > jars > vanilla; en obrigatorio, pt cai para en, en nunca recebe pt (D6). Preenche `name` de `blockDrop` (`block.<ns>.<caminho>`), `mobDrop` (`entity.`), `structurePlaced` (`structure.`, so quando o jogo tem a chave), o nome dos itens sem chave no lang do app (`item.<ns>.<caminho>`, senao `block.`; ex. os `minecraft:*`; item so com pt no kubejs ganha o en do jar) e o item segurado nas notas `special` das interactions. Itens `minecraft:*` sem textura ganham a do jar vanilla pelo modelo do item (`layer0`; item de bloco = face `all`/`front`/`side` do modelo do bloco), publicada em `assets/items/minecraft/<item>.png` com `?v=` e um quadro so se animada. Report: secao `items`, `refNames` e `vanillaTextures`.
- Pesca (spawn-bait, `src/species/fishing.ts`): todo `SpawnEntry` tem `fishing` (antes de `extra`), `null` quando o spawn nao tem condicao de pesca; senao `{ bait, rodType, rodBall, minLureLevel, maxLureLevel, lureMultipliers: [{ lureMin, lureMax, multiplier }] }`. `bait`/`rodType`/`minLureLevel`/`maxLureLevel` vem de `condition` e saem de `extra.condition` quando tem o tipo certo. Multiplicador "so Lure" = `condition` com pelo menos uma chave e so `minLureLevel`/`maxLureLevel` numericos: entra em `lureMultipliers` (o `weightMultiplier` singular primeiro, depois os de `weightMultipliers` na ordem do arquivo) e sai de `extra` (lista que fica vazia some); os outros multiplicadores (timeRange, clima...) continuam em `extra`. `rodBall` = `pokeBallId` de `data/cobblemon/pokerods/<vara>.json` (jars obrigatorios, `kubejs/data` vence); vara sem arquivo = `null` + aviso `W_SPAWN_ROD_UNKNOWN`.
- Cache: `tools/dataset/.cache/<etapa>/` (`ctx.cacheDir("pokeapi" | "sprites")`), ignorado pelo git.
- Contrato: `src/context.ts` (`PipelineContext`, `COUNT_OWNERS`: cada etapa grava so as proprias contagens com `ctx.setCount`).
